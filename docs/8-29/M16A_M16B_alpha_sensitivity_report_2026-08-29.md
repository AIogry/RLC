# M16A / M16B Puzzle GCIQL alpha 敏感性实验报告

日期：2026-08-29  
状态：M16B 的 8 个正式 run 已全部完成；本报告为单训练 seed 的完整描述性结果与 M16C 设计建议。

## 1. 结论摘要

M16B 证实：在本项目的 joint actor+value+critic Puzzle-token MLP-Mixer L2（S002）设置下，
`alpha=1.0` 并不只是把 M16A 的结果整体上移或下移，而是与网络结构发生了明显的交互。

- Flat B000 在 3x3 和 4x4 上随 `alpha: 0.3 -> 1.0` 提升（final 分别 `+0.18`、`+0.07`），但在 4x5 和 4x6 下降（`-0.07`、`-0.12`）。因此“Flat 在 alpha=1.0 明显更好”只适用于前两个环境，不能概括为全部 Puzzle 环境的结论。
- S002 在四个环境的 `final@1M` 均不高于 `alpha=0.3`：3x3 `-0.20`、4x4 `-0.24`、4x5 `-0.01`、4x6 `-0.06`。
- 3x3 的 Mixer 相对 Flat 优势从 `+0.16` 反转为 `-0.22`；4x4 的优势从 `+0.52` 缩小到 `+0.21`。这两处是当前最强的“alpha × 架构”交互证据。
- 4x5/4x6 的总体成功率很低，alpha=1.0 没有解决任务支持/学习困难；这些环境不适合在单个 seed 下被用作精确选择最优 alpha 的唯一依据。

M16C 在 4x4 上扫描 S002 的 `alpha={0.1,0.2,0.5,0.7}` 是合理的：连同已有的 `0.3` 和 `1.0`，可形成六点响应曲线。若后续确实要声称 Flat 与 Mixer 各自采用“最佳 alpha”，则建议 M16C 对 B000 和 S002 都扫描这四个新增 alpha（共 8 个新 run），而不应只扫描 S002；否则并不能知道 `alpha=1.0` 是否真的就是 Flat 的最佳值。

### 2.3 指标与限制

`final` 是 `final@1M` 的 `evaluation/overall_success`；`best` 是十个评估点的最大值；
`last-3` 是 800k/900k/1M 均值；AUC 是 100k–1M 上十个 overall success 点的梯形积分除以 900k。

每个 overall 值聚合了 5 个 task × 20 episodes = 100 个 episode，最小变化单位为 `0.01`。
所有结果只有一个训练 seed，故以下差异是效应估计而非显著性检验，不能据此宣称统计可靠的最优 alpha。

## 7. 初步机制解释：DDPG+BC 平衡改变，而非“alpha 只是标签”

当前 GCIQL 使用 DDPG+BC actor objective：

```text
actor_loss = q_loss + bc_loss
bc_loss    = -alpha * mean(log pi(a_dataset | s, g))
```

在 1M 最后一个 validation log 上，八个 B000/S002 × 环境组合中：

| alpha | validation `bc_loss` 范围 | validation `q_loss` 范围 | validation `actor_loss` 范围 |
|---:|---:|---:|---:|
| 0.3 | 1.396–1.407 | 1.000–1.000 | 2.395–2.407 |
| 1.0 | 4.634–4.663 | 1.000–1.000 | 5.634–5.663 |

因此在本实现和该训练状态下，alpha 从 0.3 升至 1.0 将 BC 项从约 1.4 提高到约 4.65，
而 Q 项仍约为 1。这意味着 actor 优化的行为克隆约束显著增强；它不是一个可以忽略的轻微标量调整。

一个与数据一致、但仍须进一步验证的解释是：S002 在 3x3/4x4 的原有收益依赖于较强的
value/Q-guided policy 改进或较宽松的偏离数据分布空间；过强 BC 权重限制了这种结构性优势。
Flat 在简单任务上可能从更强的行为约束中受益。该解释不是因果证明，因为尚未做梯度、动作偏离、Q/BC 比例随训练的正式诊断。

## 8. M16C 是否可行：结论与推荐设计

### 8.1 用户提出的 S002-only 扫描是否合理

合理。对 4x4 的 S002 新增：

```text
alpha = 0.1, 0.2, 0.5, 0.7
seed  = 0
budget/protocol = 与 M16A/M16B 完全相同
```

可与已有的 S002 `alpha=0.3`（M16A）和 `alpha=1.0`（M16B）共同构成：

```text
S002 / Puzzle-4x4 / seed 0:
0.1, 0.2, 0.3, 0.5, 0.7, 1.0
```

候选点同时覆盖 BC 相对 Q 更弱（0.1/0.2）、当前强效点附近（0.3）、及逐渐更强的 BC
约束（0.5/0.7/1.0），设计上有明确机制动机。

### 8.2 但若要比较“各自最佳 alpha”，推荐做完整 2×4 新增矩阵

只扫描 S002 足以回答“Mixer 的局部最优 alpha 大致在哪里”，但**不能**回答“Flat 的最佳
alpha 是不是 1.0”。Flat 当前只有 0.3 与 1.0 两个观测点，1.0 更好不等于它优于 0.5 或 0.7。

因此推荐的 M16C 为：

| 架构 | 新增 alpha | 新增 run |
|---|---|---:|
| B000 Flat | 0.1, 0.2, 0.5, 0.7 | 4 |
| S002 Mixer L2 | 0.1, 0.2, 0.5, 0.7 | 4 |
| 合计 | Puzzle-4x4、seed 0 | 8 |

加上 M16A/M16B 里已有的 `0.3`、`1.0`，得到一个平衡的 `architecture × alpha` 六点网格：

```text
2 architectures × 6 alpha values = 12 个 4x4 seed-0 cells
```

这比只跑 4 个 Mixer cell 多 4 个 run，但能同时回答三个不同问题：

1. 固定同一 alpha 时，S002 相对 B000 的结构效应是什么？
2. 同一架构内，alpha 响应曲线是否单峰、平坦或非单调？
3. 若为每个方法独立调参，二者各自的最优表现是多少？

### 8.3 Flat 与 Mixer 使用不同最佳 alpha 是否公平

可以，但必须区分两种科学声明。

| 比较类型 | alpha 规则 | 可以回答的问题 | 不可以声称的内容 |
|---|---|---|---|
| 控制架构比较 | B000 与 S002 使用同一 alpha | 在固定训练正则下，结构本身的条件效应 | “各方法的最好可达性能” |
| 独立调参比较 | B000 用 `alpha*_flat`，S002 用 `alpha*_mixer` | 相同 tuning budget 下两种方法的最佳调优性能 | 差异完全由 Mixer 结构本身造成 |

所以 `alpha*_flat != alpha*_mixer` 是完全可能、也在方法调优中可接受的。关键是：

- 两者必须搜索相同的候选集合、拥有相同的训练/评估预算；
- 必须报告完整网格，而不是只报告各自的最好点；
- 必须把结论写为“independently tuned Flat vs independently tuned Mixer”，而非“纯结构效应”；
- `alpha=1.0` 的官方 benchmark 复现结果应单独保留，不与调优后的非官方 alpha 混写。

### 8.4 防止 seed-0 调参偏差的选择与确认规则

建议把 M16C 的 seed-0 网格明确标为 exploratory tuning stage，并在启动前固定：

1. 主选择指标：`final@1M`，与 M16A/M16B 的既定 primary endpoint 一致；
2. 若若干 alpha 的 final 差距不超过 `0.05`，不在 seed 0 上强行选一个，而是保留为并列候选；AUC 和 last-3 仅作为稳定性诊断；
3. 选出的 Flat 与 S002 候选分别新增 seed 1–4，在 4x4 上确认；
4. 若后续想推广到 3x3/4x5/4x6，应将 M16C 选出的 alpha 看作“从 4x4 转移的假设”，而非这些环境的已证明最优值。

4x4 是合理的调参锚点，但只能定义 `alpha*_4x4`。要声称一个对所有 Puzzle 通用的 alpha，
需在多个任务上进行预先定义的、平衡的选择或确认。

## 9. 建议的下一步

1. 先将 M16C 定义为 4x4 的平衡 `B000/S002 × {0.1,0.2,0.5,0.7}` 网格，而不是只跑 S002。
2. 保持与 M16A/M16B 相同的 1M、20-episode、10 个 evaluation checkpoint 协议；alpha 必须继续在 Study、factor、`agent_overrides` 和 resolved config 中显式记录。
3. M16C 完成后，先画出每个架构自己的 final/AUC 对 alpha 曲线，再按上述规则筛选候选；不要在 M16C 完成前预设 Flat 必然选 1.0 或 Mixer 必然选 0.3。
4. 对选择出的 alpha 做多 seed 确认，然后再决定是否扩展到其他 Puzzle 尺寸、S001/S004 或 placement 拆分。
