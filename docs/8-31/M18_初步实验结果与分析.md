## 1. 先给结论

M18 的正式问题是：在表示、MLP-Mixer block、可训练参数量和训练超参数都固定时，只增加共享 recurrent computation 的执行次数 `K`，GCIQL 在 Puzzle-4x4 上是否受益。

截至本次读取：

- `K=1/2/4` 已经完整训练到 `1M`，可以做正式的描述性比较。
- `K=8` 仍处于 `running` 状态，已有 `100k` 到 `500k` 五个评估点，训练日志约到 `545k`，没有 `1M` 的 final endpoint，也没有 last checkpoint。
- 因此目前不能给 `K=8` 排名，也不能计算正式的 `100k–1M` normalized AUC；只能把它当作一个很强的中途异常信号。
- 在已经完成的三个条件中，整体形态是：`K=4` 学得最快，`K=1` 的最终结果与它接近，`K=2` 明显较弱。
- `K=8` 在 `500k` 仍只有 `0.08`，远低于同一步数下的 `K=1: 0.71`、`K=2: 0.53`、`K=4: 0.80`。这值得重点调查，但还不能区分“只是延迟学习”与“深度导致退化”。

最稳妥的当前表述是：

> 在一个 seed 的 Puzzle-4x4 实验中，增加共享 recurrent execution 从 `K=1` 到 `K=4` 带来了明显的早期学习速度收益；但尚未显示 1M 最终成功率收益。`K=2` 没有复现这种收益，`K=8` 截至 500k 表现严重落后，最终结论必须等它跑完 1M 并完成后验诊断。

这不是统计显著性结论，也不是“最佳 K”的结论。M18 只有 `seed=0`。

### 2.1 K 改变的是执行量，不是参数量

M18 的一个关键点是：每次 recurrent iteration 复用同一个两层 Mixer stack，而不是复制新的 stack。形式化地，若 adapter 产生 token 表示 `X`，则每次 forward 是：

```text
Z^0 = 0
Z^(k+1) = B_theta^(L=2)(Z^k + X),  k = 0, ..., K-1
output = Readout(Z^K, context)
```

这里的 `B_theta` 在 K 次中共享参数，但 `MLPMixerBlock` 自己仍保留 token/channel mixing 的内部 residual。因此 `topology residual=false` 并不等于 Mixer 内部没有 residual。

实际 accounting 如下。参数是 online GCIQL 的 actor/value/critic 总量；actor 的 MAC 和 depth 是单一路径口径。

| K | 总可训练参数 | actor 参数 | actor unique Mixer | actor executed Mixer | actor body Dense MAC | actor buffer | actor executed depth |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 1,112,712 | 278,437 | 2 | 2 | 2,773,760 | 128 | 10 |
| 2 | 1,112,712 | 278,437 | 2 | 4 | 5,395,200 | 128 | 18 |
| 4 | 1,112,712 | 278,437 | 2 | 8 | 10,638,080 | 128 | 34 |
| 8 | 1,112,712 | 278,437 | 2 | 16 | 21,123,840 | 128 | 66 |

所以这里研究的是“同一个可训练变换被执行更多次”，不是更宽或更多参数的网络。

代码位置：

- `SingleState` 的 `z+x`、zero buffer 和 K 次循环在 [`impls/computation/topologies/single_state.py`](../../impls/computation/topologies/single_state.py) 的 `step` 和 `__call__`。
- structured factory 强制 `state_dim=token_dim`、identity mapping、shared、`residual=false` 的位置在 [`impls/computation/factory.py`](../../impls/computation/factory.py)。
- Mixer 自身的 token/channel residual 在 [`impls/computation/blocks/mlp_mixer.py`](../../impls/computation/blocks/mlp_mixer.py)。
- token mean 与 context 拼接、fusion Dense 在 [`impls/computation/readouts.py`](../../impls/computation/readouts.py)。

K=2: 0.17, 0.34, 0.41, 0.37, 0.53, 0.70, 0.69, 0.75, 0.73, 0.74

### 3.3 应该怎样读这个结果

#### K=4：最强的证据是早期学习速度

`K=4` 在 300k 已达到 `0.71`，而 `K=1` 到 400k 才达到 `0.61`，`K=2` 到 600k 才达到 `0.70`。它的 normalized AUC 为 `0.7633`，高于 K=1 的 `0.6672` 和 K=2 的 `0.5528`。

这支持一个较窄的结论：在当前 Puzzle、GCIQL、seed 0 和 M18 transition 下，K=4 可能让策略更早形成可用的决策表示。

但 K=4 的 final 是 `0.89`，K=1 是 `0.90`，二者几乎相同；K=4 的 best `0.98` 后又回到 `0.89`。因此不能说 K=4 最终性能显著超过 K=1。更准确的说法是“sample-efficiency/early-learning 更好，最终持久优势尚未证明”。

#### K=1：最终稳定性不差，不能把它当作失败 baseline

K=1 的 best 是 `0.95`，last-3 mean 是 `0.9167`，final 是 `0.90`。它的曲线虽然前期慢于 K=4，但到后期达到相近水平。

这说明增加 computation 的收益可能主要是优化轨迹的改变，而不是最终函数表达能力的增加。因为 K=1 已经拥有完整的两层 Mixer 和相同的参数量，并不是一个“没有结构”的弱 baseline。

#### K=2：非单调性信号

K=2 的 final `0.74`、AUC `0.5528`、last-3 `0.74` 都低于 K=1 和 K=4。它不是单纯“更多 K 一定更好”的曲线，而是出现了 `K=1 > K=2 < K=4` 的非单调现象。

这可能来自：

1. 共享 transition 在恰好两次执行时落在不利的表示几何区域；
2. actor、value、critic 同时改变，优化路径发生了相互作用；
3. 单个 seed 的训练方差；
4. K=2 的 hidden state 分布与最终 readout/actor head 的匹配不如 K=1 或 K=4。

仅凭一个 seed 不能选出其中哪一个是真因。重要的是，不要把它简化成“recurrent computation 无效”。

#### K=8：中途表现是异常，但还不是最终结论

K=8 的 5 个评估点为 `0.08, 0.12, 0.07, 0.10, 0.08`，任务级最后一次为：

```text
task1=0.10, task2=0.00, task3=0.25, task4=0.00, task5=0.05
```

这不是只在某一个 task 上失败，而是几乎所有 task 都没有形成有效策略。它说明 K=8 至少存在以下两种可能之一：

- 需要远多于 500k 的 optimizer steps 才能学起来；
- 大 K 下 repeated-input recurrence 造成了不利的 hidden-state dynamics，使 actor/value/critic 的学习信号难以转化为成功行为。

目前训练日志没有出现 NaN，critic loss 从约 `1.48` 降到 `0.37`，gradient norm 从约 `4998` 降到 `1516`。所以当前更像“目标函数数值看起来正常，但行为没有学会”，而不是简单的数值爆炸。这个判断仍需等 1M 和 K-test 诊断确认。

## 5. 为什么训练 loss 正常，evaluation 却可能很差

这是分析 offline RL 时最重要的思维方式之一：训练 loss 是 surrogate objective，不等价于任务成功率。

GCIQL 的 DDPG+BC actor loss 在 [`impls/agents/gciql.py`](../../impls/agents/gciql.py) 中近似为：

```text
actor_loss = q_loss + alpha * (-log_prob(data_action))
q_loss = -mean(Q(s, goal, actor_action)) / stop_gradient(mean(abs(Q)) + eps)
```

因此：

- `actor_loss` 接近，不代表两个 actor 产生的动作一样好；
- `q_loss` 被 `abs(Q)` 归一化，数值接近 1 并不代表 Q 学得很好；
- `q_mean`、`q_abs_mean` 的负值本身不一定是异常，关键要看相对变化、预测误差和 action ranking；
- `critic_loss` 变小只说明 TD 拟合的 surrogate 误差变小，不保证 Q 在 OOD action 上的排序正确；
- `value_loss` 也不能单独证明 actor 得到了正确的 goal-conditioned value landscape。

当前结果恰好说明这一点：K=2 在 1M 时 critic loss 约 `0.27`，比 K=1 的约 `0.37` 更小，但 evaluation success 却只有 `0.74`，明显低于 K=1 的 `0.90`。不能用“loss 更小”推出“策略更好”。

分析时要沿着这条因果链检查：

```text
K 增加
  -> Z^K 的数值尺度、方向和 token 间关系改变
  -> mean_context readout 的输出改变
  -> actor head 的动作分布和 critic 接收的状态/目标分布改变
  -> Q 对动作的排序和 actor 梯度改变
  -> 实际 deterministic action 改变
  -> Puzzle 任务成功率改变
```

如果 loss 正常但 evaluation 很差，问题很可能出现在这条链的后半段：representation 的几何虽然能让训练目标下降，却没有产生能够解决任务的 action ranking。

## 6. 从指标推理模型问题：一套可复用的方法

### 第一步：先做完整性和可比性审计

在解释任何曲线前，先检查：

1. `runtime_metadata.status` 是否为 `completed`；
2. `eval.csv` 是否包含预期的全部 steps；
3. `resolved_config.json` 中真正生效的 K、L、alpha、slot placement 是否正确；
4. dataset path、commit、seed、batch、eval episodes、temperature 是否一致；
5. 参数量是否固定，K 是否真的通过 shared module 扩展；
6. checkpoint 的 best/last 是否存在，best step 是否只是中途偶然峰值。

M18 的自动聚合器是 [`tools/analyze_m18.py`](../../tools/analyze_m18.py)，它会把 partial run 的 final 和 AUC 留空，不把不完整结果伪装成完整结果。典型命令是：

```bash
python tools/analyze_m18.py \
  --study experiments/M18_puzzle_recurrent_compute_scaling/study.yaml \
  --run-root /data/qijunrong/06-RL/offline-rl/exp/RLC/runs \
  --output-dir docs/8-31/M18_results
```

### 第二步：同时看 final、best、末期窗口和 AUC

推荐按这个顺序解释：

| 现象 | 首要含义 | 不应直接推出 |
|---|---|---|
| final 高 | 训练预算结束时表现好 | 整个训练过程都好 |
| best 高但 final 低 | 后期退化或评估噪声 | best 就是稳定能力 |
| AUC 高 | 平均学习更快/更早有效 | final 一定更高 |
| last-3 高 | 末期相对稳定 | 没有更早的退化 |
| 四者都低 | 可能是整体学习失败 | 一定是实现 bug |

例如本次 K=4 的 AUC 最好、final 与 K=1 接近，说明“速度优势”比“最终优势”更可信；K=4 的 best-final gap 为 `0.09`，说明还要关注后期稳定性。

### 第三步：按 task 拆开，而不是只看 overall

若 overall 下降，先问是：

- 所有 task 一起下降：更像共享表示、actor/critic 协同或全局优化问题；
- 只有一个 task 下降：更像 task-specific representation、goal sampling、动作精度或该 task 的难度问题；
- 不同 task 交替涨跌：可能是共享模型容量竞争、训练目标漂移或评估 episode 数太少。

M18 K=8 的 task2、task4 为 0，task1、task5 也接近 0，不是单一 task 难度造成的局部问题；但 K=8 仍未完成，所以暂时不能把它定性为永久 collapse。

### 第四步：用 train/validation gap 判断泛化还是训练本身

观察 `train.csv`：

- train loss 下降、validation loss 上升，且 eval 下降：典型 overfitting 或 train/val 分布差异；
- train 和 validation 都稳定，但 eval 很差：更像行为实现、Q 的 OOD extrapolation、representation/readout 或 evaluation protocol 问题；
- train/validation 都发散，grad norm 同时尖峰：优先查数值稳定性、学习率、normalization、recurrent state scale；
- loss 稳定但 success 长期为 0：不要继续只盯 loss，要直接看 actions、Q ranking 和 hidden state。

M18 K=8 目前 train/validation 的 actor loss 都约为 `2.86`，critic/value 指标有限且没有 NaN，支持“不是显式数值崩溃”的初步判断。

### 第五步：正确解读 Q、V 和 actor 指标

至少要区分：

- `training/actor/q_mean`：actor 当前动作经过 critic 的 Q；
- `training/critic/q_mean`：代码中记录的是 TD target 的均值，不是简单的 critic prediction mean；
- `q_abs_mean`：actor Q 的绝对值尺度；
- `critic_loss`：TD 拟合误差；
- `value_loss`：expectile value objective；
- `bc_loss`：actor 模仿数据动作的代价；
- `mse`：actor mode 与数据 action 的均方误差；
- `grad/norm`：整体梯度规模，只能帮助判断更新是否异常，不能直接代表性能。

若 `q_abs_mean` 持续变大、`grad/norm` 也变大、critic loss 发散，优先怀疑 Q scale 或 recurrent hidden state 不稳定。若这些都平稳而 success 低，优先检查动作实现和 Q 的错误排序，而不是马上改学习率。

### 第六步：用“最小验证实验”区分候选原因

对于类似 M18 的结果，建议按成本从低到高进行：

1. **重新评估同一个 checkpoint**：增加 episode 数，确认 best-final 差距是否只是 20 episode 的采样噪声。
2. **确定性 action 检查**：记录每个 task 的 action 均值、方差、是否饱和到 `[-1,1]` 边界、与 dataset action 的 MSE。
3. **Q ranking 检查**：在同一状态下比较 dataset action、actor action 和若干扰动 action 的 Q；如果 Q 认为 actor action 好，但环境不成功，说明 critic 有 OOD 错误或 action semantics 有问题。
4. **K-train × K-test**：固定一个已训练 checkpoint，只改变 inference 时执行多少次 recurrence，不做 optimizer update。M18 已有 [`tools/m18_cross_k_eval.py`](../../tools/m18_cross_k_eval.py) 及 M18-D 设计。
5. **hidden-state trace**：记录 `Z^0...Z^K` 的 RMS、最大值、`||Z^(k+1)-Z^k||`、token 间方差和最终 readout norm。这能直接判断是 exploding、vanishing、oversmoothing 还是没有形成稳定 fixed point。
6. **slot isolation**：只替换 actor、只替换 value/critic，判断退化来自 policy realization 还是 value learning；这应作为独立后续实验，不能在当前 M18 中临时改配置。
7. **多 seed replication**：只有在科学问题和诊断条件冻结后再做，用来区分结构效应和 seed variance。

## 7. 对 K=8 当前异常的深入推理

### 7.1 最值得优先排查：repeated input injection 的 hidden-state dynamics

当前 recurrence 是：

```text
Z^(k+1) = B(Z^k + X)
```

每一轮都把同一个 `X` 加进去，同时 `B` 内部还有 Mixer residual。如果局部近似为 `B(U) ≈ U + f(U)`，那么 recurrence 会近似包含：

```text
Z^(k+1) ≈ Z^k + X + f(Z^k + X)
```

这意味着 K 增加不只是“多看几次同样的信息”，还可能使 hidden state 的尺度、方向和 token 间关系不断偏移。K=8 可能落入：

- state norm 随 iteration 增长，导致 readout 输出尺度变化；
- update 变成过度平滑，不同 token 变得相似；
- update 逐渐趋于饱和，新增计算只重复错误表示；
- actor 和 critic 对不同深度形成了不同的 input distribution，训练与最终行为脱节。

这只是最合理的机制假设，不是从现有日志直接证明的事实。因为当前 forward 没有保存中间 `Z`，必须用 state trace 或 K-test 验证。

### 7.2 为什么“没有 NaN”仍然可能是算法问题

有限值只说明浮点计算没有立即失败。一个 recurrent model 完全可能在有限数值范围内产生错误的表示：

```text
数值有限
  ≠ hidden representation 有效
  ≠ critic ranking 正确
  ≠ actor action 能解决 Puzzle
```

K=8 的 critic loss 下降而 success 很低，正是这种“优化了 surrogate，但没有学到任务行为”的典型警告形态。

### 7.3 K=8 也可能只是需要更多 optimizer steps

当前比较是在相同 `500k` optimizer steps 下进行的，不能排除 K=8 需要更长的 warm-up。尤其 K=8 每次 forward 更深，虽然每步看到的 batch 数量相同，但优化 landscape 可能不同。

因此项目协议要求 K=8 继续跑到 1M，不能因为中间 success 低就提前停止。只有在 1M 仍低，才能把“深度造成退化”的假设提升为主要候选。

### 7.4 最有效的区分实验：K-train × K-test

对一个 `K_train=8` 的完整 checkpoint：

- 如果在 `K_test=1/2/4` 时成功率明显恢复，而 `K_test=8` 很差，说明模型可能已经学到可用 transition，但执行太深导致 over-processing 或 distribution shift；
- 如果所有 `K_test` 都很差，说明问题可能早在训练中发生，可能是 actor/critic 联合优化没有学到可用函数；
- 如果 `K_train=1/2/4` 的 checkpoint 在 `K_test=8` 也普遍变差，说明当前 transition 对 inference depth 很敏感；
- 如果不同 `K_test` 都接近，说明 K 的主要影响不在单次 forward depth，而可能在训练优化轨迹。

这个矩阵必须是 evaluation-only、no finetuning、no checkpoint rewrite，不能把它解释成 adaptive test-time computation。

## 8. 当前应该怎样写实验结论

可以写：

> 在 seed 0 的 Puzzle-4x4 GCIQL 试验中，固定 trainable parameter count 后，K=4 相比 K=1/2 展现出更高的 normalized evaluation AUC，表明其早期学习更快。K=1 与 K=4 的 final@1M 接近，因此目前更支持 sample-efficiency 改善，而不是最终成功率改善。K=2 在本 seed 下表现较弱，显示 scaling 非单调。K=8 截至 500k 仍为 partial run 且成功率很低，需完成 1M 与后续 K-train × K-test/state-dynamics 诊断后再解释。

不要写：

- “K=4 是最优 K”；
- “K 越大越好”；
- “K=8 已经证明失败”；
- “critic loss 最小的 K=2 最好”；
- “没有 NaN，所以 K=8 算法没有问题”；
- “K=1 和 K=4 的 0.01 差异是真实优势”。

## 10. 一套日常分析 checklist

以后拿到一个新实验目录，可以按下面顺序快速判断：

```text
[完整性]
status / eval steps / checkpoint / 非有限值
        |
[可比性]
commit / dataset / seed / protocol / resolved config / params
        |
[行为结果]
final / best / best step / last-3 / AUC / task-level curve
        |
[训练动态]
actor / BC / Q scale / critic TD / value / grad norm / train-val gap
        |
[机制定位]
数值崩溃？过拟合？Q 错排？action 饱和？state dynamics？task-specific failure？
        |
[验证]
复评 checkpoint -> action/Q probe -> K-test -> state trace -> isolation -> multi-seed
```

核心原则只有一句：先确认“现象是真的且可比”，再用 task-level behavior 和 hidden-state/Q/action 证据解释原因，最后才修改算法或超参数。
