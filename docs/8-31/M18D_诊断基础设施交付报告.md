## 1. 旧 D1 工具原本如何工作，以及为什么必须改

旧的 tools/m18_cross_k_eval.py 将 source resolved config 中 actor、value、critic 三个 slot 的 topology iterations 一并覆盖为 test K，并且默认 selector 是 last。它也沿用了 source run 必须 completed 的通用约束。

这与本轮预注册问题不一致。本轮 D1 的问题是：

    对固定 joint-trained source K，actor 的行为是否会随 actor inference depth 改变？

因此当前 D1 的运行时 config 是：

    source: actor=value=critic=K_train
    D1 test: actor=K_actor_test; value=critic=K_train

rollout action generation 只调用 actor。metadata 明确记录：

- K_train 与 K_actor_test；
- test_time_override 仅为 compute.actor.topology_kwargs.iterations；
- value_critic_runtime_iterations=K_train；
- value_or_critic_used_for_rollout_action_generation=false；
- paired evaluation seed protocol。

这不是说 value/critic 对训练毫无作用；它们在 source checkpoint 的训练中仍以 joint K 参与了目标与优化。D1 只是避免在测试阶段把它们的 execution depth 也伪装成一个 actor-depth intervention。

原 M18 study/config 中留下的 old cross-K placeholder 仍未修改。它是 frozen scientific configuration，不是本轮 D1 的权威执行语义；权威语义在新工具与本报告的手动命令中明确给出。

## 2. checkpoint=best 与 running K8 的安全策略

D1/D2/D3/D4 第一版统一只接受 checkpoint=best。

在 impls/experiment/reevaluation.py 的 validate_source_run 中增加了一个极窄的参数：

    allow_running_source_if_checkpoint_best=True

只有同时满足下列条件时，source status=running 可以被接受：

1. selector 已规范化为 best；
2. source runtime metadata 合法；

## 4. normal forward、parameter tree 与 checkpoint restore

normal SingleState 的数学仍为：

    Z0 = broadcast(z_init)
    Z(k+1) = step(Zk, x_hidden)

其中 M18 shared topology 的 step 仍执行完整的 L=2 shared Mixer update。trace_states 只是显式重复同一个已经存在的 step，并返回：

    (Z0, Z1, ..., Zmax)

对于 shared topology，diagnostic 可以在 source K_train=4 的参数下计算到 Z8；对于 untied topology，超过其已有 update module 数量会拒绝执行。M18 使用 shared，所以不重新初始化、也不复制 Mixer block。

trace_states、trace_tokens 和 diagnostic_trace 不创建 param 或 variable。定向测试验证了：

- Z0 在 M18 zero_buffer 语义下严格为 0；
- trace 的 ZK 与 normal SingleState forward 数值一致；
- 在显式 trace 前后计算 normal forward loss 的 parameter gradient 逐叶完全一致；
- actor trace 在训练 K 处的 unclipped mean 与 normal deterministic actor mode 一致；
- 调用 trace 前后 parameter path、buffer path 和 TrainState step 不变；
- K_train=1 source 用 actor test K=8 重建时，actor/value/critic 分别为 8/1/1，且 parameter count 相同；
- legacy-style M18 checkpoint 可 restore；
- 当前真实 K4 best checkpoint 可 restore。

## 5. D2：state trace 与精确定义

每个 slot 的 structured trace 使用同一个 restored adapter、同一个 context、同一个 MeanContextReadout：

    token_states:   [B, Kmax+1, T, D]
    readout_states: [B, Kmax+1, H]

critic 是 ensemble，故其 token/readout trace 额外有 ensemble axis。每个 recorded iteration 都是一个完整 recurrent step，不是 Mixer 内部 Layer 1/Layer 2 的中间输出。

设一个 sample 的 token state 为 Z^k 属于 R^(T x D)，epsilon 固定为 1e-8。输出以下 per-sample/per-step metrics，并在 trace_summary.csv 汇总 mean、std、median、p10、p25、p75、p90：

| Metric | 定义与索引 |
|---|---|
| state_rms | sqrt(mean(Z^k squared)) |
| absolute_update_from_previous | RMS(Z^k - Z^(k-1))，k=0 为 NaN |
| relative_update_from_previous | norm(Z^k-Z^(k-1)) / (norm(Z^(k-1))+epsilon)；k=0、1 为 NaN，因为 Z0=0 不作机制解释 |
| state_cosine_from_previous | cosine(vec(Z^k), vec(Z^(k-1)))；k=0、1 为 NaN |
| token_variance | token 相对该 sample mean-token 的均方偏差 |
| pairwise_token_cosine | 排除对角线后的 token cosine 均值；zero norm 用 epsilon 稳定 |
| mean_token_rms | RMS(mean over tokens of Z^k) |
| readout_rms | RMS(同一 restored MeanContextReadout(Z^k, context)) |

absolute update 的 CSV iteration_k 表示 update 的终点 k，即 iteration_k=4 对应 Z4-Z3。这样每个行的 state 与 update 对齐，metadata 中也记录了定义。

## 6. D3：deterministic intermediate action refinement

对 actor 的每个 Z^k：

    h^k = same restored readout(Z^k, context)
    mu^k = same trained actor mean head(h^k)
    a^k = clip(mu^k, -1, 1)

没有采样，没有 Gaussian noise。保存的 actor_metrics.npz 同时包含 unclipped_action_mean 与 clipped_action。

核心 D3 指标：

| Metric | 定义 |
|---|---|
| action_delta_from_previous | RMS(a^k-a^(k-1))；primary 值从 k=2 开始 |
| action_drift_from_k1 | RMS(a^k-a^1)，k>=1 |
| action_mean_saturation_fraction | fraction(abs(mu_j^k)>=1.0) |
| action_near_boundary_fraction | fraction(abs(a_j^k)>=0.95) |
| dataset_action_mse | mean_j((a_j^k-a_dataset_j) squared) |

normal actor mode 的数值校验比较的是 unclipped mean，因为 normal GCActor mode 本身是 mean；环境 action 与 D3 critic-action comparison 使用 clip 到 [-1,1] 后的 a^k。

## 7. D4：critic-action consistency

D4 固定 source critic 的训练 execution depth K_train，不会随着 actor intermediate k 改变 critic K。对同一个 fixed batch 的 actor actions a1 到 aKmax 计算：

    Q1(s,g,a^k), Q2(s,g,a^k)
    Qmin^k = min(Q1, Q2)
    Qgap^k = Qmin(s,g,a^k) - Qmin(s,g,a_dataset)

并保存 q1、q2、qmin、qgap_vs_dataset_action、critic_disagreement=abs(Q1-Q2)。其解释必须是：source critic 如何为同一 controlled offline (s,g) 上的不同 actor action 排名；它不是环境 return，也不是因果证据。

定向测试把 final intermediate action 输入普通 critic call，逐元素核对 D4 的 q1/q2，结果一致。

## 8. fixed offline diagnostic batch 与可复现性

默认 batch-size=1024，diagnostic-seed=18018。工具从 source metadata 所指的 Puzzle-4x4 train dataset 建立 GCDataset，使用：

    rng = numpy.default_rng(diagnostic_seed)
    indices = dataset.dataset.get_random_idxs(N, rng)
    sampled = dataset.sample(N, idxs=indices, rng=rng)

独立 diagnostics 目录保存：

- fixed_batch.npz：sample_id、sample_indices、observations、actor_goals、value_goals、dataset_actions；
- fixed_batch_metadata.json：dataset path/class、seed、N、shape、fingerprint、reference source config/run；
- 逐 job 的 m18d_metadata.json：batch fingerprint 与 source provenance。

为让 actor/value/critic trace 比较的是同一个 controlled (s,g) batch，本轮三者都使用已保存的 actor_goals。value_goals 仍保存为原始 GCDataset draw 的 provenance，但不替代 trace 的共享 g；这一点在 fixed_batch_metadata.json 的 goal_semantics_rationale 中明确记录。

再次请求同一 batch root 时，工具不重新采样，而会校验 N、seed、environment、source study、dataset directory、字段集合和 SHA256 fingerprint。Tiny real-data test 已确认同 seed 的二次读取逐数组一致。

## 9. source checkpoint immutability 与零更新保证

每个 D1/D234 job：

1. 在 restore 前对 semantic checkpoint 做稳定 SHA256（连续两次 hash 与 stat 一致）；
2. 验证 hash 与 semantic metadata/index 匹配；
3. 只构建 fresh agent 并 restore；
4. 完成后再次稳定 hash；
5. 要求 before==after，否则 job 失败。

所有 metadata/summary 都记录：

    evaluation_only = true
    finetuning = false
    optimizer_updates = 0
    source_checkpoint_immutable = true

diagnostic code 不调用 agent.update、apply_loss_fn、optimizer.step 或 resume training，也不在 source run 下创建 metadata、optimizer state 或 diagnostic 文件。

10. Qmin；

每张图标注 checkpoint=best，并在 legend 中标明 K_train 和 slot。报告自动生成下列 hypothesis 的 descriptive decision table：

    H_overprocessing
    H_state_instability
    H_token_oversmoothing
    H_action_instability
    H_critic_misalignment
    H_training_failure

状态只会使用 consistent、not observed、mixed、insufficient evidence。它不会输出 causal TRUE/FALSE，不会合成所谓 overthinking score。特别地：

- RMS 增长只说明 representation scale 改变；
- token cosine 接近 1 必须与 token variance 下降一起看；
- Q 与 success 的相关性不等于 critic error；
- M18 当前训练 seed=0，不能作显著性或泛化结论。
