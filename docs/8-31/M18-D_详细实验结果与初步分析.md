# M18-D：详细实验结果与初步分析

> 日期：2026-08-31  
> Study：M18  4x4 Puzzle 结构化 token + MLP-Mixer computation  
> Algorithm：GCIQL  
> 诊断：M18-D1 / M18-D2 / M18-D3 / M18-D4

## 1. 报告结论

M18-D 完成后，当前最可靠的结论有四点：

1. **当前的 K 是训练阶段绑定的计算深度，不是可以在测试时自由调节的计算预算。** 每一个模型只有在自己训练时的 actor 深度上表现正常；改变 `K_actor_test` 后，所有非对角线结果都降为 0。
2. **K=8 的低性能不能只解释为测试时“算得太多”。** 对 K=8 checkpoint 降低测试深度到 1、2、4 都不能恢复成功率，因此失败已经存在于 K=8 的训练结果或训练时的深层状态动力学中。
3. **K=8 没有呈现简单的数值爆炸、token oversmoothing 或动作饱和。** 它的 state 轨迹相邻 cosine 最终约为 0.87，相对更新量下降到约 0.49，说明状态趋于稳定；但它可能稳定在一个不适合 Puzzle 任务的错误表示吸引子上。
4. **K=8 的 critic-action 关系存在值得重点调查的异常。** 在固定 offline batch 上，critic 对深层 actor action 的 `qgap_vs_dataset_action` 从 0.128 增加到 0.845，但真实 rollout 成功率仍然只有 0.15；这提示 critic 的动作排序可能与真实长时序任务效果脱钩，但还不能据此断言存在唯一的 critic 过估计原因。

因此，下一步最值得调查的方向是：K=8 训练阶段的长计算路径、深层状态到 readout 的监督、critic 对 actor action 的排序，以及这些 Q 判断在真实 rollout 状态分布上是否仍然成立。

## 2. M18 与 M18-D 的实验对象

### 2.1 M18 的固定结构

M18 的四个条件只改变 joint computation depth K；actor、value、critic 三个 slot 使用同一个 K。主要结构为：

| 配置项 | 设置 |
|---|---|
| 环境 | `puzzle-4x4-play-v0` |
| 算法 | GCIQL |
| 结构 | `puzzle_tokens` |
| token 数 | 16 |
| token dim | 128 |
| computation block | 2 个 MLP-Mixer block，`L=2` |
| topology | `single_state` |
| parameter sharing | `shared` |
| state 初始化 | `zero_buffer`，即 `Z^0=0` |
| 输入映射 | `identity` |
| 输入注入 | `z+x` |
| readout | `mean_context` |
| residual | `false` |
| alpha | 0.4 |
| training seed | 0 |
| 总 trainable parameters | 1,112,712；四个 K 相同 |

由于 computation block 采用 shared 参数，增加 K **不会增加参数量**，但会增加同一个 block 的执行次数、路径长度和反向传播深度。

可以将单个 slot 的计算抽象为：

```text
Z^0 = 0
Z^{k+1} = B_theta(Z^k + X)
Y^K = Readout(Z^K, context)
```

其中 `B_theta` 是共享的 computation block。训练时的 actor head 主要接收训练深度对应的 `Z^K`。

### 2.2 M18-D 的四个诊断

| 诊断 | 目的 | 数据范围 |
|---|---|---|
| D1 | 解耦训练时 K 和测试时 actor K | 4x4 个 `K_train x K_actor_test` 单元，共 16 个单元 |
| D2 | 追踪 computation state 的变化 | K=4、K=8；固定 offline batch；k=0..8 |
| D3 | 追踪中间 computation state 对动作的影响 | K=4、K=8；确定性 actor mean |
| D4 | 比较 critic 对 actor action 与 dataset action 的评价 | K=4、K=8；source-K critic |

M18-D 全部是 evaluation-only diagnostic：

- 不进行 finetuning；
- `optimizer_updates=0`；
- source checkpoint 不覆盖；
- D2-D4 使用同一个固定 batch，大小为 1024；
- D1 每个单元 5 个 task、每个 task 20 个 episode，共 100 个 episode；
- 评估种子为 `18018`。

因此，M18-D 的数值适合做机制比较，不应被误解成新的训练结果或多 seed 统计结论。

### 5.3 D1 的含义

D1 说明当前模型并没有学到一个对 computation depth 具有鲁棒性的函数族。每个 K 条件实际上都在学习：

```text
特定输入分布 -> 特定深度的 Z^K -> readout/action
```

它没有学习：

```text
任意中间状态 Z^k -> 都能被同一个 readout 正确解释
```

因此，D1 的结果并不表示 computation block 在数学上只能运行一次固定 K，而是表示**当前训练目标没有保证不同深度下的表示和 readout 兼容**。

### 6.2 对 D2 的解释

#### K=4：训练深度之后仍发生明显状态漂移

K=4 在 k=4 时 state RMS 为 0.5444；继续执行到 k=8 后上升到 0.8377。相对更新量在 k=4 和 k=8 都接近 1，说明每一步仍然会产生较大变化。

这与 K=4 的 D1 结果相符：k=4 是训练和 readout 校准的深度，k>4 属于 depth extrapolation。模型在训练之外继续运行时，表示不再保持原来的分布。

#### K=8：状态趋于稳定，但不能据此认为表示正确

K=8 在 k=8 时：

- state RMS 为 0.6739；
- relative update 为 0.4907；
- state cosine 为 0.8735；
- readout RMS 约为 0.2576。

这些数值没有显示出明显的数值发散。相邻状态越来越相似，说明重复 computation 可能正在接近某种稳定状态。

但 token variance 从 0.0507 增长到 0.4273，pairwise token cosine 从 0.4467 降到 0.0413。因此 K=8 不是典型的 token oversmoothing；token 没有变成完全相同的向量，反而变得更加分化。

当前更合理的表述是：

> K=8 形成了一个相对稳定但可能错误的 computation attractor。内部数值稳定和任务行为正确是两个不同问题。

### 7.2 对 D3 的解释

K=4 在训练深度 k=4 的 dataset action MSE 最低，为 0.0227；继续执行到 k=8 后升至 0.0442，同时 action drift 增大到 0.1560。这说明 K=4 的 depth extrapolation 会明显改变动作。

K=8 则不同：

- action delta 从 k=2 的 0.0628 下降到 k=8 的 0.0263；
- k=8 的 dataset action MSE 只有 0.0262；
- saturation fraction 只有 1.74%；
- near-boundary fraction 约 3.96%。

因此，K=8 的低成功率不能简单解释为动作剧烈震荡或动作全部饱和。它更可能是“动作变化不大，但在 Puzzle 的关键时刻存在任务关键的细微错误”。

Puzzle 是长时序任务，平均动作距离很小仍然可能导致某一次按钮交互失败，随后整个 episode 进入无法恢复的状态。因此 dataset action MSE 不能替代真实 rollout 成功率。

K=8 的 qgap 则近似单调增加：

```text
k=1: 0.1277
k=4: 0.2364
k=8: 0.8446
```

同时 K=8 的真实成功率只有 0.15。这形成了一个需要重点调查的脱钩现象：

```text
critic 认为深层 actor action 越来越好
        但环境中的任务成功率并没有相应提高
```

这可能来自：

1. critic 在 offline state 上对略微偏离 dataset 的 action 进行乐观外推；
2. critic 学到的是单步或局部价值，而 Puzzle 的真实难点是长时序动作序列；
3. actor 访问的 rollout state 分布与固定 offline batch 不同；
4. 两个 critic 共同继承了相似的错误估计，因此较小的 disagreement 不等于估计正确。

这里不能直接说“qgap 大就一定是 Q overestimation”。`qgap` 只是 source critic 在固定 batch 上对两类 action 的相对打分，不是真实环境 return。

自动分析脚本将 `H_critic_misalignment` 标为 `not observed`，是因为它使用了 success 与 qmin 的简单相关性启发式。这个标签是非因果、阈值很弱的自动判断，不应覆盖对原始 qgap 曲线的人工分析。

## 9. 对候选机制的初步判断

| 候选原因 | M18-D 结果 | 当前判断 |
|---|---|---|
| 测试时 K=8 过度计算 | K=8 改成 K=1/2/4 后仍为 0 | 不支持“仅测试时过深”解释 |
| computation 数值发散 | K=8 relative update 下降、state cosine 上升 | 没有明显证据 |
| token oversmoothing | variance 上升、pairwise cosine 下降 | 不支持典型 oversmoothing |
| actor 动作剧烈震荡 | K=8 action delta 下降 | 不支持 |
| actor 动作完全饱和 | K=8 饱和比例约 1.74% | 不支持 |
| K=8 训练阶段失败 | 主实验 best=0.12、final=0.03，D1 对角线仅 0.15 | 当前最符合，但不是因果证明 |
| critic-action misalignment | K=8 qgap 随深度升至 0.845，而成功率低 | 有较强警告，需要额外验证 |

## 10. 总体机制推理

把 M18-D 的结果串起来，当前最合理的工作假设是：

```text
K=8 训练阶段需要学习一条更长的共享 computation 链
                    ↓
深层状态逐步稳定，但可能稳定在错误表示区域
                    ↓
readout 产生看似平滑、接近 dataset 的动作
                    ↓
critic 在 offline state 上给这些动作越来越高的 Q
                    ↓
actor 缺少能够指向真实长时序成功的纠正信号
                    ↓
rollout 中出现长时间停滞和 task-level 失败
```

这里的关键词是“稳定但错误”，而不是“发散”。稳定性指标只能说明 computation 没有明显崩溃，不能说明它学到了有用的任务表示。

此外，当前所有 K 的参数量相同，K=8 的失败不能简单归因于参数更少或模型容量直接变小。更可能的差异来自：

- 重复 block 带来的更长优化路径；
- 只有最终 `Z^K` 得到直接任务监督；
- 深层 actor/value/critic 的目标彼此耦合；
- `single_state + shared + residual=false` 对长期迭代的稳定性和信息保留能力有限；
- critic 对深层 action 的离线外推可能改变 actor 的训练方向。

## 11. 结论边界

本报告中的结论需要遵守以下边界：

- M18 只有 training seed=0；
- M18-D1 使用 best checkpoint，不是 final checkpoint；
- D1 的 D1 diagonal 数值和 M18 主实验 best 数值使用不同评估种子，因此不应逐点比较为“训练结果矛盾”；
- D2-D4 只有 K=4、K=8；
- D2-D4 使用固定 offline batch，不是 actor rollout state distribution；
- D4 的 Q 值不能直接等同于 environment return；
- 当前结果支持候选机制，但不能证明唯一因果关系。

## 12. 建议的后续验证

### 12.1 区分 checkpoint 问题与深度问题

对 M18 的 `best` 和 `final` 都执行 D1，尤其是 K=8。这样可以回答：

```text
K=8 的低性能主要来自 checkpoint 选择，还是所有训练阶段都存在深度问题？
```

### 12.2 训练时加入多深度监督

训练 K=8 时，不只使用 `Z^8`，还可以对 `Z^1...Z^8`：

- 同时计算 actor loss；
- 同时计算 value/critic loss；
- 或随机采样训练深度；
- 或给中间深度增加 auxiliary loss。

如果这样显著恢复跨 K 泛化，说明原始问题主要是 readout 与最终深度绑定。

### 12.3 直接验证 critic 是否失配

在真实 rollout 状态上记录：

- `Qmin(s_rollout, a_actor)`；
- `Qmin(s_rollout, a_dataset-like)`；
- 成功 episode 和失败 episode 的 qgap；
- Q 值和最终 success 的对应关系。

这比只在固定 offline batch 上比较 actor action 与 dataset action 更接近真正的行为问题。

### 12.4 结构消融

建议优先比较：

1. `residual=false` 与 `residual=true`；
2. 有无 LayerNorm；
3. `single_state` 与更适合长期迭代的 state update；
4. K=8 下 shared block 与不共享 block；
5. zero initialization 与其他 state initialization。

### 12.5 增加统计可靠性

至少增加多个 training seeds，并固定：

- dataset；
- eval seed 集合；
- checkpoint 选择规则；
- D1 的 episode 数；
- D2-D4 的 fixed batch。

只有这样，才能判断 K=8 的失败和 qgap 异常是否具有跨 seed 的稳定性。
